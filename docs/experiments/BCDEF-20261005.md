# Experimental BCDEF graphics runtime

This is an offline-built candidate, not a promoted display-tested release. The
installed Candidate B broker, module, launcher, and session were left unchanged.
All C/C++ and kernel builds ran on root@192.168.104.201. No C–F module was loaded,
no Magisk ZIP was installed, and no HDMI session was restarted during preparation.

## Profiles

| Launcher profile | Enabled changes | Companion requirement |
|---|---|---|
| B | Timing guard and asynchronous TearFree; experimental Mesa features off | Existing B or new presenter companion |
| C | B plus persistent asynchronous bridge, separate submission/completion, bounded resize generations and deferred resource retirement | Existing B or new presenter companion |
| D | B+C plus private application rendering and same-context resolve into Xorg-owned shared images | Existing B or new presenter companion |
| E | B plus eligible glamor GL blits and actual Freedreno CP_BLIT counters | Existing B or new presenter companion |
| F | B plus kernel-deferred fence-ready primary-plane flips | New presenter companion and matching broker |
| BCDEF | All of the above; D uses C's persistent transport | New presenter companion and matching broker |

`run-agent.sh` defaults to BCDEF. `run-C.sh`, `run-D.sh`, `run-E.sh`, `run-F.sh`,
and `run-BCDEF.sh` pin profiles; `--candidate` can also select them directly.
The B profile in this new runtime still includes the unconditional imported-buffer
identity correction. Use the unchanged original B bundle for an exact historical
binary comparison, before upgrading its companion, or restore its rollback module.

The launchers require matched private Mesa ABI 6, Xorg/glamor, and the appropriate
loaded companion identity. C/D have no CPU-readback fallback. E keeps ordinary
shader copies for unsupported GC operations, incompatible formats, overlapping
images, large pixmap tiling, or unsuitable damage. No target-MSC lead was changed.

## Concrete implementation

C has one private X connection and persistent presentation worker per drawable.
Native producer and copy fences are polled with X completion/idle events; the
shared submission mutex is released before GPU execution completes. FIFO request
ordering and the existing +2 MSC priming lead are preserved. A scanout slot cannot
be reused until both completion and idle notifications match its presentation.
SBC advances on real Present completion, rather than enqueue. Resizes retain at
most three destination generations with three slots each and a 512 MiB destination
allocation limit, plus a bounded 16-entry producer retirement queue. Admission can
apply backpressure. CPU-side submission/fence export can still block briefly.

D retains efficient private application images and resolves from the current
application context into an imported Xorg-owned image. DRI's existing GL-thread
ordering and resource flush are preserved; a final native fence covers rendering
and resolve. The worker sends ordinary Present only after readiness. Native GPU
fences are never passed as X11 shared-memory fence objects. Full-image copies are
intentional here; partial resolves need per-slot damage history and remain future
work. Front-buffer and other nonstandard rendering are not promoted optimized
paths. New generations retire after actual users finish.

An independently reproduced sharing defect was fixed in the experimental Mesa:
KGSL handle export could shadow an externally imported resource into new storage
because its bind flags did not identify it as shared. The producer then rendered
into storage different from the consumer's original DMA-BUF. Imported KGSL images
now retain `PIPE_BIND_SHARED`, preserving storage identity during metadata export.
Before the fix, the two-process test read black; afterwards it passed 60 checks in
12 cases, including 65x63, 257x193, 1919x1079 and 3840x2160 images. The producer
never maps or reads the shared image before consumption.

E adds guarded `glBlitFramebuffer` copies to glamor. It does not remove overlap
scratch buffers. Mesa counts actual emitted hardware-blit work separately from
API requests. The changing-pattern benchmark poisons destinations and checks
multiple positions, including pixels outside partial regions: 3,744 checks passed.
Synthetic timings vary by layout and fragmentation; this is not proof of improved
physical desktop latency. The existing direct-render path remains available as a
separate allocation experiment, not a replacement for D or the normal bridge.
Eliminating the final root-to-scanout copy or introducing a compositing backend is
outside this release and must not be inferred from the candidate name.

F's additive module validates the exact currently guarded lease, generation,
external connector, CRTC and primary plane. It retains the file, DRM objects,
framebuffer and native acquire fence. It accepts one FIFO request per presenter
and at most four presenters. Fence callbacks schedule a private kernel workqueue;
only that worker takes modeset locks and uses the existing atomic-helper page-flip
path. No modesets, GPU-ioctl proxy, or alternate DRM event reader are added. Both
signalled and cancelled DRM events retire ownership; submitted commits cannot be
pretended cancelled. Per-flip vblank ownership balances on actual event retirement.
Xorg distinguishes copy-pending work from a submitted flip, including completion
arriving before the companion status wakeup. Ordinary DRM completion carries MSC
and UST. F has compiled/ABI validation only; live cancellation and display behavior
are still pending.

## Offline validation and pending gates

The full repository source/native checks passed, including timing capability
negotiation with and without the additive presenter bit, broker stop handling,
tracer acknowledgements and USB/Bluetooth fan-in. All 45 selected Xorg units were
rebuilt. The additive module passed version/CFI verification against the exact
installed kernel configuration and pinned symbol versions. Hardware-dependent
build-server tests were skipped where no device exists, rather than called passes.

Tests on the phone used the isolated private Mesa for offscreen images only.
They did not connect to X, modeset, change a lease, or read back the producer's
shared image in the two-process test. These checks do not exercise the live Xorg
pipeline or kernel presenter.

When the monitor returns: first finish B's controlled comparison, then test C,
D, E and F separately against the same activities. D necessarily includes C's
transport. Test teardown, crash, unplug/replug, suspend/resume, resize storms,
patterned partial damage and actual physical cadence. Only after the individual
profiles pass should BCDEF be tested. Obtain the user's unplug confirmation before
any session restart. Leave experimental Magisk installation to the user; the ZIP
and rollback ZIP are staged in /hostMounts/sdcardext.
