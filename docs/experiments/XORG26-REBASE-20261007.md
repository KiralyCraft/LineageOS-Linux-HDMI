# Xorg 26 migration candidate

Branch: `feature/xorg-26-rebase`. This follows the
[upstream assessment](XORG-UPSTREAM-AUDIT-20261007.md). The target is the official
Xorg 26.1 RC3 archive, version `26.0.99.903`, with evdev `2.11.0` rebuilt against
its generated SDK. `build-support/xorg26-sources.json` pins both archives by URL
and SHA256. This is an experimental userspace candidate; physical acceptance is
pending and no Magisk or native broker change is required.

## Patch selection

The active series is `patches/xserver26/series`:

- 0001: disarm legacy wait-fence callbacks before re-execution.
- 0004: release temporary damage regions on all relevant paths.
- 0005: fence-driven TearFree with distinct copy-pending and submitted-flip states.
- 0006: the original E ABI 1 eligible-copy blit experiment.
- 0007: the existing kernel companion deferred-presenter integration.
- 0010: GPU-complete consumer release for ordinary Present copies.

The render-node preference (old 0002) and large TearFree backport (old 0003) are
already upstream and are omitted. E ABI 2 diagnostics (0008/0009) remain separate
historical experiments, matching the comparison bundle's E ABI 1 selection.
The old patch directory and submodule pin remain solely for older build recipes.

The port follows upstream's `HAVE_GBM` guards, new include locations, allocator
names and damage-dispatch signature. Patch 0010 preserves the upstream explicit
release-syncobj branch and fences only the ordinary legacy Present copy branch.
No private protocol is added and no syncobj capability is falsely advertised.

## Clean build

Run native builds only on `root@192.168.104.201`, in `mesa-arm-builder`:

```sh
python3 build-support/build-xorg26.py REPOSITORY ARCHIVE_DIRECTORY NEW_OUTPUT
```

The script refuses an existing output, verifies archives, applies the rebased
series without fuzz, configures a new Meson tree at O2, builds all targets, runs
upstream tests, and stages installation. It then builds evdev using the staged
server SDK, runs the consumer-release ASan/UBSan fixture, and checks exported
entry points and compiled feature markers. It reuses no 21.1 object files or
generated headers. Ordinary development dependencies must already be installed;
evdev additionally requires libevdev and mtdev headers. The runtime test servers
also require xkeyboard-config data at the configured XKB path.

`--resume` reconstructs the pinned sources and patches in a temporary directory,
compares every reference source file and the configured Meson options, and only
then resumes the existing clean build. This permits recovery from a missing test
dependency without accepting changed source or reusing the older 21.1 build.

On this build host the cached mirror entry for libevdev 1.13.6 returned 404.
The signed libevdev 1.13.7 package from the phone's package cache was supplied to
the build container, matching the phone's runtime. mtdev is 1.1.7. No phone
package was changed.

The first compile completed all 628 build steps. The initial test run passed the
module-symbol check but failed to initialize keyboards because the container
lacked xkeyboard-config. Installing the phone-matching signed 2.48 package in
the container resolved those startup failures. The monolithic unit test then
exceeded Meson's native 30-second default under ARM emulation. The build script
uses a bounded 5x timeout multiplier for this emulated build environment. The
optional XTS suite requires an external xtest checkout and is reported as skipped
when that checkout is absent; it must not be reported as a test pass.

The corrected upstream run completed with **5 passed, 0 failed, 1 skipped**;
the unit suite took 42.8 seconds. evdev compiled against input ABI 26.0; the
server also provides video ABI 28.0 and extension ABI 11.0. The final module
check includes evdev in addition to upstream's original GLX/glamor/modesetting
set. The package supplies all those private modules together.

LeakSanitizer cannot inspect threads under QEMU user emulation. The ARM lifecycle
fixture keeps AddressSanitizer and UndefinedBehaviorSanitizer enabled while
disabling leak detection. The same fixture is also compiled and executed directly
on the build host with all its default sanitizers, including leak detection.
The native host run passed all six consumer-release lifecycle/error scenarios.
These are stubbed ownership tests, not GPU/scanout acceptance.

`--validate-staged` verifies the same source/configuration and successful upstream
test results before restaging and performing only final module/lifecycle checks.
Meson's install plan removes build-directory RPATHs; raw and installed GLX module
hashes consequently differ. Packaging verifies the installed artifact hashes,
not a false equality with the uninstalled module.

Final build validation succeeded: 564 compilation units, all required feature
markers and exported hooks present, staged GLX/glamor/modesetting/evdev modules
loaded successfully by the upstream symbol checker, and all six release-fixture
scenarios passed on both ARM (ASan/UBSan) and the native build host (including
LSan). The final result is recorded in `validation/xorg26-build.json`; sanitizer
and module-check output accompanies it. GPU presentation and HDMI lifecycle
acceptance remain pending.

## Bundle and comparison

`build-support/package-xorg26.py` starts from the preserved Downloads bundle
`hdmi-termux-vblank-min-coexist-usb-bt-bcdef-release-queue-20261007`. It replaces
the complete private Xorg module tree, including GLX and evdev, along with Xorg.
It copies that bundle's newest launcher and adds checks for the new private
module set. It verifies that the Mesa, native binaries, interposer and kernel
companion bytes remain unchanged. Source archives, the exact patch selection,
build/test metadata and complete file hashes accompany the new folder.

The intended folder is:
`~/Downloads/hdmi-termux-vblank-min-coexist-usb-bt-bcdef-xorg26-20261007`.

It retains continuous BCDEF, E ABI 1, `release=fence`, and
`queue=low-latency`. Mesa remains `557306b5c`, including the resize cache and
queue fixes. The USB/Bluetooth fan-in bridge is unchanged; its Xorg evdev
consumer is rebuilt for the new SDK.

The comparison bundle is the rollback and the controlled Xorg 21.1 baseline.
Do not use source version numbers or successful builds as physical evidence.
Acceptance still requires visible startup, input, numbered frames, glxgears
resizing, windowed OpenJK, and unplug/return-to-Android testing. The waiting
agent and user applications must remain untouched until the user's requested
confirmation before restarting HDMI.
