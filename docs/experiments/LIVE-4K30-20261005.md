# Combined candidate: 4K30 display tests, 2026-10-05

The user manually installed and rebooted with the experimental BCDEF Magisk
module. Two bounded 60-second sessions used the combined userspace runtime at
3840x2160@30. The monitor was available without a keyboard or mouse. Input,
4K60 performance, and a controlled latency comparison were not tested.

Compiled revisions: HDMI kernel `12df706428a0`, native agent/broker and Xorg
patch set `a336e421`, Mesa `170a56fa943cc475472d170157efe58d7dd9b8c1`.
The visible test source was introduced by HDMI commit `322050cc12f7`.

## First bounded display smoke

The user confirmed that the Linux desktop appeared and the timer returned the
monitor to Android. Logs identified hardware glamor, asynchronous TearFree, the
eligible glamor-copy backend, and the kernel presenter. The session timing
reference balanced and the companion reference count returned to zero after
cleanup. No accelerated client was exercised in this first smoke.

The first Xorg log did not contain a normal successful-exit marker. This remains
an unresolved observation; restoration of Android alone does not prove graceful
Xorg shutdown.

## Accelerated client and resize smoke

The second session ran `tests/graphics-contract/leased-window.py`. FD740 and
private Mesa were verified. The client used the persistent C transport and D's
application-context resolve, with 16 destination generations over the test.
Mesa reported 447 submitted and 447 completed Present operations,
447 integrated resolves, and zero worker copies. Actual Freedreno hardware-blit
emission was observed. Xorg recorded eligible glamor blits and the F presenter.

| Phase | Submitted frames | Swap-call p50 | Swap-call p95 |
|---|---:|---:|---:|
| Fixed 800x600 | 149 | 1.52 ms | 1.84 ms |
| Move and resize | 149 | 1.59 ms | 17.62 ms |
| Fixed afterwards | 149 | 1.51 ms | 1.97 ms |

Each phase lasted approximately five seconds and the client was paced at
30 submissions per second. These are application swap-call measurements,
not physical scanout FPS or input-to-display latency. No baseline was measured.

Xorg logged `Server terminated successfully (0)` for this second session.
The timing reference again balanced and the companion reference count returned
to zero after full broker cleanup. Cleanup took roughly six seconds. Private
process samples show Xorg had already exited and remained a zombie while the
agent's `kill(pid, 0)` liveness loop waited before calling `waitpid`; this explains
at least part of the stop delay, without resolving the first exit observation.

**Physical graphics correctness failed.** The user reported initial blue dots
on the titlebar and colorful corruption in the first frame after a window
transition. These disappeared after later updates. The initially stationary
color-changing viewport was clean, both initially and during updates.
Successful Present counters and offscreen pixel checks do not override this
physical failure. The combined candidate is not promoted.

## Next controlled comparison

The original test deliberately remains available for reproduction. It mapped a
window without defining a background and resized before redrawing; it did not
handle ConfigureNotify or Expose. Newly exposed contents before the first valid
redraw are therefore a possible test confound. This is not a diagnosis of the
reported corruption, especially the titlebar artifacts.

`tests/graphics-contract/leased-pattern.py` defines black backgrounds and fully
redraws a recognizable four-color pattern at actual configured dimensions. It
keeps a plain X11 reference stationary and splits stationary, move-only,
resize-only, and combined phases. It performs no GPU-image readback. Its geometry
queries add request round trips, so its timings are correctness-test diagnostics.

The `BCDF` profile disables only the eligible Xorg blit optimization (E) while
retaining the timing guard, asynchronous TearFree, persistent Mesa transport,
application-context resolve, kernel presenter, and the same compiled binaries.
Comparing BCDF and BCDEF with this same test isolates that Xorg backend switch.
The CPU/GPU driver, broker and installed module do not need replacement.

The BCDF result is recorded below. Raw runtime and process observations stay
private under `.local/`; this report contains the sanitized results only.

## BCDF corrected-pattern control

After the user's unplug confirmation, the waiting agent was switched to the
separate controls bundle and the broker armed for another bounded 4K30 session.
The same compiled binaries and installed module were retained. Process
environment checks confirmed C, D and F enabled with E's Xorg copy switch absent;
the Xorg log confirmed the kernel presenter and contained no eligible-copy
activation marker. Mesa's application-context resolve still used the hardware
blitter: disabling E does not disable accelerated client transfers.

The corrected pattern test completed all five phases. The user reported:
"It seemed fine, i saw no artficats at all". This is a successful **visual smoke
test for BCDF at 4K30**, not general acceptance of every lifecycle or workload.

| Phase | Submitted frames | Swap-call p50 | Swap-call p95 | Maximum |
|---|---:|---:|---:|---:|
| Stationary | 120 | 8.46 ms | 15.28 ms | 16.58 ms |
| Move only | 120 | 1.46 ms | 2.09 ms | 5.89 ms |
| Resize only | 120 | 1.60 ms | 14.99 ms | 44.29 ms |
| Move and resize | 118 | 1.59 ms | 15.15 ms | 256.14 ms |
| Stationary afterwards | 120 | 1.48 ms | 1.88 ms | 2.07 ms |

Mesa recorded 598 submitted and 598 completed Present operations, 598 integrated
resolves and zero worker copies, using 13 destination generations. Xorg again
logged successful normal termination. After the 60-second lease and complete
cleanup, Android owned the display and the companion reference count was zero.

The single 256 ms swap-call outlier remains unexplained. Geometry queries,
full patterned redraws and explicit client pacing make this a correctness
harness; these measurements do not establish physical latency or a speedup.

Two things changed relative to the original artifact-producing test: the
application now defines its background and handles actual geometry, and E is
disabled. This run alone therefore **does not establish E as the cause**.
A matched E-on comparison remains pending. The user accepted the resize-cache
and restricted-E changes below before the next physical comparison.


## Resize-cache and restricted-E follow-up

The next runtime defaults to **BCDF (E off)**. The same corrected-pattern harness
and installed companion/broker are retained. This is a new userspace build;
the preceding visual result does not automatically validate it.

The existing Mesa implementation discarded all idle destination generations on
a size miss and created/imported the replacement while holding the lock needed
by the presentation worker. The 13 generations above served only three sizes.
The new C/D implementation caches up to three sizes, reuses matching idle slots,
and evicts the least recently used fully idle generation when necessary. Every
non-free slot pins its generation. The actual imported allocation sizes control
the existing 512 MiB bound. Retirement finishes before replacement allocation,
so deferred cleanup does not add unbounded generations.

Allocation/import and destruction run outside the event-processing lock. A
separate X connection carries allocation replies; the presentation worker owns
the Present event connection. Buffer creation still takes time on a cache miss,
but it no longer excludes completion-event processing. Teardown summaries split
admission, generation/slot waits, allocation, retirement, resolve submission and
fence export. Histogram percentiles are bucket upper bounds, not exact p95s.
This is a targeted inefficiency fix, not proof of the cause of the 256 ms outlier.

E is compiled but remains disabled by default. Patch 0008 removes its hook from
generic glamor copies. Its dedicated interface only accepts distinct compatible
root/TearFree pixmaps; modesetting limits calls to unrotated origin-aligned
TearFree buffers. Texture-only FBO metadata (framebuffer ID zero), invalid
geometry, aliased images, incomplete attachments and GL failures fall back to
the established accelerated shader-copy path. Framebuffer bindings and scissor
state are restored. This closes a source-level validation gap; the original
physical artifacts have not been attributed conclusively to that gap.

Build-host tests compile the actual production cache and blit helpers against
mock resource/GL boundaries with address and undefined-behavior sanitizers. They
exercise cache reuse, padded allocation budgets, busy-generation pinning,
retirement, failure cleanup, wait/stop, blit eligibility and GL state restoration.
These tests do not validate actual GPU visibility, display correctness or timing.
The unchanged live pattern test is the next physical gate, first with E off.

was rebuilt on the designated server from 12,793 verified tracked files. All
